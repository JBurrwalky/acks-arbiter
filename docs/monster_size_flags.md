# Monster Size / Footprint — Status

Generated by the creature-size build session from `docs/monster_size_audit.xlsx`. **227 of 236** catalog entries now carry a grid footprint; the remaining **9 are the monster swarms**, which are a diffuse enveloping *area* (`swarm_area` block + `SwarmDriver`), NOT a solid footprint (coding_conventions §126). Every non-swarm entry is now wired. Any un-wired entry renders and collides as a single 1×1 cell — the safe default in `CreatureSize.footprint_local`.

## Wired — resolved groups (227)

- **Confident audit rows (155)** — the original pass (incl. the 10 `dragon_*` age entries from the audit's Dragon Age tab).
- **Elementals (12)** — DONE 2026-07-20. Size from RAW (`le_monster_catalog_6.xml` `*_form_dimensions`, per-HD); footprints authored and **decoupled** from the size tier (a tall-thin whirlwind / radial fire-water don't fit the scale), carrying a `size_decoupled` marker: Air 1×1 / 1×1 / 2×2; Earth 1×1 / 1×2 / 2×2; Fire 2×2 / 3×3 / 3×3; Water 3×3 / 5×5 / 7×7 (8/12/16 HD). Pinned by `test_elemental_sizes_from_raw`.
- **`skeleton`** — DONE 2026-07-20. Empty RAW `<stat_block/>` was an extraction artifact; catalog HD 1 + humanoid → man_sized 1×1 (matches sibling `zombie`).
- **Uncertain body form (41)** — DONE 2026-07-22..24. Key finding: the audit self-flagged these because its weight formula (run on a *guessed* body form) was unreliable — the catalog's size tiers were the sound values. Resolved by adopting catalog size (normalized to ACKS terms) + audit orientation: winged/quadruped beasts (griffon, hippogriff, pegasus, manticore, lamia, lammasu, centaur) → large 2×1 long; man-sized folk (shadow, spectre, merman, rust_monster, throghrin) → man_sized 1×1; broad-bodied large (djinni, efreeti, invisible_stalker, iron/stone/crystal statues) → large 1×2 wide; cockatrice, stirge → small 1×1; gorgon, chimera → huge 2×2; titanothere, treant → huge 2×2; remorhaz → gigantic 4×3 long; dragon_turtle → colossal 6×9; skittering_maw → large 2×1 long; **all hydras → gigantic 4×3 long** (this added a gigantic long/wide orientation to `CreatureSize`); **lycanthropes → animal-form footprint** (= base animal, large 2×1) + a `man_form_footprint` [1,1] field (ACKS 1e weres are fully-animal OR fully-man; the dynamic swap awaits a shapeshift system).
- **Thin-bodied (4)** — DONE 2026-07-24 (RAW gives no size text for these; the weight formula under-sizes long/thin bodies, so they were length calls): `bee_giant` small 1×1; `caecilian` gigantic **6×1** (30′ worm-amphibian, decoupled); `octopus_giant` huge 2×2; `purple_worm` colossal **11×5** (decoupled, 11 long × 5 wide).
- **Swarms (9: `insect_swarm_2/3/4hd` + `bat_swarm_2/3/4hd` + `rat_swarm_2/3/4hd`)** — DONE 2026-07-24. A swarm is **not a footprint case** — it is a diffuse, NON-blocking *enveloping area* (RAW 10′×30′, HD-scaled), handled by a separate `swarm_area` block + `SwarmDriver`, NOT a solid `footprint` (footprint stays 1×1). The full monster-swarm combat subsystem shipped: area geometry (`Combatant.get_swarm_area_local` + `CreatureFootprint.area_cells`), the insect/bat/rat effect types (2-pt tick / Confusion-save / Paralysis-save→prone+1d6+disease), the general rules (ward-off + warding/fleeing halve, 3-round flee persistence, 1-round water clear, damaged-swarm + LOS pursuit, sleep→dormant, fire/cold full damage), and the new `bat_swarm_*` / `rat_swarm_*` catalog entries. See `coding_conventions §126`; tests `tests/test_swarm_monsters.gd` + `tests/test_swarm_conditions.gd`.

- **Herd / domestic animals** — DONE 2026-07-24 (chip `task_0d130ed9`, the last non-swarm flag group). The four `herd_animal_<hd>` placeholders (a bloc standing in for dozens of species) were **broken into 9 real terrain-specific species** with true RAW-sourced stat blocks + footprints: `herd_animal_antelope`, `herd_animal_deer`, `herd_animal_wild_goat`, `herd_animal_wild_sheep` (1-2 HD, man_sized/large), `herd_animal_caribou`, `herd_animal_aurochs` (3 HD, large), `herd_animal_bison`, `herd_animal_elk`, `herd_animal_moose` (4 HD, large). Species taxonomy + HD + butt damage from the `acore_monster_catalog_gol-lee.xml` Herd Animals `typical_species` table (1-2 HD antelope/deer/goats = 1d4; 3 HD caribou/cattle/oxen = 1d6; 4 HD buffalo/elk/moose = 1d8); the RAW-named Antelope/Goat/Sheep placed per the `acore-monster-stocking-rules.xml` wilderness encounter tables, the rest by the RAW "region and climate determine the specific kind" population rule. Size labels from `daw_campaigns_troop_tables_summary.xml` + `le_monster_training_rules.xml` (1 HD = Man-sized, 2/3/4 HD = Large; **RAW caps every tier at Large** — heaviest 1,400 lb < 2,000 lb Large ceiling, so none reach Huge). `save_as` = `fighter(hd/2)` (`le_monster_creation.xml:93`), XP per its `xp_table`. Wired into the wilderness encounter resolver via `terrain_affinity` (each species surfaces in exactly its RAW terrain columns) and into `wilderness_creature_table.json` domain-encounter membership (per-HD battle ratings from `ax_domain_level_encounters.xml`). The 5 concrete domestic livestock — `cow`/`ox` (large 2×1 long), `sheep`/`goat`/`donkey` (man_sized 1×1) — got their footprints in the same pass. Pinned by `tests/test_monster_footprint_data.gd` (herd-species footprint/stat integrity + terrain-column-resolves-to-real-id consistency; no dangling `herd_animal_<hd>` refs).
