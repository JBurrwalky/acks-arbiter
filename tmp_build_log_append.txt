
## Session 2026-05-22 — Per-race tribal-warrior composition import shipped

**Task:** Import the RAW Tribal Warrior Troop Type table from `ax_domains_of_chaos.xml:417-444` + per-troop-type stats from `daw_campaigns_troop_tables_summary.xml`. Replace the v1 stub `tribal_infantry` template with a real per-race composition that drives the levy handler to spawn multiple troop_units rows per a race's RAW breakdown.

**Model used:** Sonnet — data transcription + helper logic + handler refactor + tests.

**Completed:**

### TribalWarriorRegistry per-race tables

- **`_COMPOSITION_PER_120`** — full RAW `ax_domains_of_chaos.xml:417-444` table transcribed as dict-of-dicts keyed `{race: {troop_type: count_per_120}}`. 11 races/cultures: jutland, iv_kingdom, skysos, kobold, goblin, orc, hobgoblin, gnoll, lizardman, bugbear, ogre. Counts verified to sum to 120 per race.
- **`_TROOP_TYPE_STATS`** — per-troop-type wages (cp), supply (cp), battle_rating-per-warrior, is_cavalry flag for 12 troop types: light_infantry, heavy_infantry, hunters, slingers, bowmen, crossbowmen, longbowmen, composite_bowmen, light_cavalry, medium_cavalry, horse_archers, beast_riders. Values derived from `daw_campaigns_troop_tables_summary.xml` representative entries (NM tier).
- **`VALID_TRIBAL_RACES`** — exported list of all 11 race/culture strings for validation.

### New helpers

- **`inferred_tribal_race_for_domain(domain_id) -> String`** — three-layer race inference: (1) explicit `domain.tribal_race` (future schema); (2) establishment_method inference (`clanhold_annex`/`recruit_chieftain` → `orc`; else → `jutland`); (3) hard fallback. Returns `""` for non-clanhold domains.
- **`composition_for_race(race, total_count) -> Array`** — scales the per-120 composition to `total_count`, distributing the integer-rounding residual to the largest-count troop type. Returns `Array[Dictionary{troop_type, count, wage_cp, supply_cp, br_per_warrior, is_cavalry}]`. Empty array on unknown race or non-positive count.
- **`base_morale_modifier_for_domain_morale(current_morale) -> int`** — RAW `ax_domains_of_chaos.xml:451-453` one-time modifier: +1 if Steadfast (+3) / Stalwart (+4); -1 if Demoralized (-1) or worse; 0 otherwise.
- **`default_template_for_domain(domain_id) -> Dictionary`** — back-compat wrapper retained for v1 callers; new callers should use `composition_for_race` directly.

### LevyTribalWarriorsHandler refactor

- Replaced single-template spawn with multi-unit composition spawn.
- **NEW `_spawn_levied_units_from_composition`** — iterates each composition row, chunks at `UNIT_SIZE_CAP` per row if needed, creates one troop_units row per (troop_type, chunk). Examples:
  - **Orc 120 levy** → 5 rows: 44 light_infantry, 30 heavy_infantry, 20 bowmen, 20 crossbowmen, 6 beast_riders.
  - **Kobold 120 levy** → 1 row: 120 light_infantry.
  - **Skysos 120 levy** → 5 rows: 30 light_infantry, 25 composite_bowmen, 20 light_cavalry, 25 horse_archers, 20 medium_cavalry.
  - **Jutland 100 levy** → 3 rows: 50 light_infantry + residual, 25 heavy_infantry, 25 bowmen (per the scaling-with-residual rule).
- Departure log entry now includes the full composition + race + morale_modifier in the payload + a human-readable composition summary in the `summary` field.
- The RAW domain-morale base-morale modifier (`base_morale_modifier_for_domain_morale`) is now applied to each spawned unit's morale field at creation time.

### Conventions §72 appended

Six patterns documented:
- RAW tables transcribed as nested-dictionary constants (transpose to dict-of-dicts keyed by the most-queried dimension).
- `per_N` normalization in the constant; scaling logic in the helper.
- Residual assignment to the largest-count category preserves source intent at non-modular sizes.
- Inference helpers with documented priority order beat magic defaults.
- Per-troop-type stat tables stay separate from race composition (different growth dimensions).
- Existing-test refactoring strategy for single-row → multi-row output changes.

**Decisions made:**

- **`orc` as the default beastman race + `jutland` as the default kin race.** Per RAW encounter tables, orcs are the most common beastman; per the user's culture-canon mapping note, Jutland covers the Germanic/Nordic human range (cultures 6/7/8). Both are sensible v1 defaults; player override lands when the future culture-canon GDD adds the explicit `domains.tribal_race` column.
- **Stats derived from NM-tier representative entries** in DaW summary. The DaW tables list A/B/C/D variants per troop type with stat spreads; v1 picks one representative value per type. Future polish could read the L&E per-race monster catalog to provide race-tier-specific stat overrides (e.g., hobgoblin light_infantry has different AC than orc light_infantry).
- **Residual goes to the largest-count troop type.** Alternative: distribute residual across all categories proportionally. Chosen approach: simpler + preserves the dominant troop-type signature at any levy size.
- **`lizardman` included in the table** even though they're not strictly beastman per the project's race set. Per RAW the table lists them; v1 honors the table directly. No clanhold currently infers to lizardman; future polish or explicit schema may surface them.
